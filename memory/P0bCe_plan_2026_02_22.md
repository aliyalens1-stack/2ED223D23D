## Goal

Increase **discoverability** of the 4 existing chronology surfaces (customer booking timeline, provider booking timeline, inspector job timeline, admin booking-forensic) **without changing chronology semantics**.

Mechanism: app scheme `asearch://` + stateless resolver `GET /api/deeplink/resolve?ref=<ref>` that returns ONLY `{surface, route, params, requiredRole}`.

---

## Guardrails (frozen contract)

1. **Resolver is NOT a permission engine.** It returns target+requiredRole. Caller may be unauthenticated. Real authorisation stays on the target endpoint / screen guard.
2. **No universal links.** Only app scheme (`asearch://`). Universal links are a separate release/deploy concern (apple-app-site-association, assetlinks.json, domain ownership, signing).
3. **No changes to chronology screens.** No new props, no new auth wrapper, no new context.
4. **No shared deep-link kit / generic link framework.** Just a resolver module + linking listener.
5. **8 baseline smoke suites MUST stay green at close** (recorded in `P0bCe_smoke_baseline_2026_02_22.md`).

## Scope (4 chronology surfaces)

| Surface key | expo-router route | Required role | WS counterpart |
|---|---|---|---|
| `booking-timeline.customer` | `/customer/booking/[id]/timeline` | `customer` | `GET /api/customer/bookings/:id/timeline/stream` |
| `booking-timeline.provider` | `/provider/booking/[id]/timeline` | `provider` | `GET /api/provider/bookings/:id/timeline/stream` |
| `job-timeline.inspector` | `/inspector/jobs/[jobId]/timeline` | `inspector` | `GET /api/inspector/jobs/:id/timeline/stream` |
| `booking-forensic.admin` | `/admin/booking/[id]/forensic` | `admin` | `GET /api/admin/booking-lifecycle/:id/stream` |

Naming intentionally mirrors the WebSocket scope conventions already established. **Not** `booking/timeline/admin` — that conflates ontology. Admin path stays `booking-forensic`.

---

## Ref format

```
<surface-key>:<resource-id>
```

Examples:
- `booking-timeline.customer:test-req-abc123`
- `booking-forensic.admin:bookng-xyz`
- `job-timeline.inspector:test-job-001`

Plain text. **NOT signed**. The resolver does not protect resource access; the target endpoint does (existing P0.b.C.a..d invariants). Signing would imply this is a permission engine — explicitly out of scope.

Deep-link URL:
```
asearch://link?ref=<url-encoded-ref>
```

## Backend changes

### New: `/app/backend/app/system/deeplink.py`

```python
GET /api/deeplink/resolve?ref=<ref>
→ 200 { surface, route, params, requiredRole }
→ 400 { error: "INVALID_DEEPLINK", message } — for malformed ref or unknown surface
→ 422 — for missing ref query param
```

- No authentication required (and no role check). Endpoint identical for unauth / customer / provider / admin callers.
- Pure stateless lookup table (no Mongo).
- Whitelisted surface keys (closed set of 4).
- Returns `route` as a printable expo-router path template (`/customer/booking/[id]/timeline`) plus `params: { id: "..." }` for clarity.

### Wiring: `/app/backend/server.py`
- Register `app.system.deeplink.router`.

### NO changes to:
- existing `/api/customer/...`, `/api/provider/...`, `/api/inspector/...`, `/api/admin/...` timeline endpoints
- existing WS streams
- existing auth/JWT pipeline
- `app/system/*` other modules

## Frontend changes

### New: `/app/frontend/src/deeplink/index.ts`

```ts
parseDeeplinkUrl(url: string): { ref: string } | null
resolveDeeplink(ref: string): Promise<ResolveResult>
navigateDeeplink(url: string, router: Router): Promise<NavigateOutcome>
```

`NavigateOutcome`:
- `{ ok: true, surface, route, params }` — pushed
- `{ ok: false, code: "INVALID_URL" }`
- `{ ok: false, code: "RESOLVE_FAILED" }`
- `{ ok: false, code: "ROLE_MISMATCH" }` ← **NOT terminal**, screen guard handles it. The deep-link layer logs and still navigates. Justification: keeping role-gating in one place (screen guard / endpoint) prevents two divergent permission surfaces.

### Edit: `/app/frontend/app/_layout.tsx`
Add (minimal, additive):
- `Linking.getInitialURL()` on mount → `navigateDeeplink`
- `Linking.addEventListener('url', …)` → `navigateDeeplink`
- Listener cleanup on unmount

### Edit: `/app/frontend/app.json`
- `"scheme": "frontend"` → `"scheme": "asearch"`

### NO changes to:
- the 4 chronology screens (no new params, no new guards)
- auth context

## New test

`/app/backend/test_deeplink_resolver_smoke.py` — pure HTTP, no Mongo:

1. 4 surfaces × happy path → returns expected route/requiredRole/params
2. Unknown surface (`unknown.surface:x`) → 400 INVALID_DEEPLINK
3. Malformed ref (missing `:`, empty id) → 400 INVALID_DEEPLINK
4. Missing `?ref=` → 422
5. **Resolver opacity invariant:** unauth call vs admin-token call vs random-role call → all return identical JSON. (Proves: not a permission engine.)

- Deep-link analytics / attribution

These belong in P0.b.C.e+1 or later, NOT this PR.

## Anti-pattern checklist (must NOT happen)

- ❌ Resolver checks JWT
- ❌ Resolver returns different shape for different callers
- ❌ Deep-link layer becomes the auth boundary
- ❌ New generic `<DeepLinkProvider>` context
- ❌ Universal-link config (`associatedDomains`, `intent-filters`)
- ❌ Chronology screens read deep-link state directly
- ❌ Ref encoding leaks transport details (no `?ws=true` etc.)
